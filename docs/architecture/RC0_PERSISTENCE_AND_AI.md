# RC0-R1 ownership and AI boundary

Runtime baseline stays Godot4.7.2. LimboAI1.8.1 is the official `limboai+v1.8.1.gdextension-4.6.zip` artifact (minimum4.6, executed on4.7.2), SHA-256 `0910411f8dbc0da8920f6c8bbbb6397c347cd9f2f193942468a702dfb11d5f0e`. `scripts/install_limboai.sh` verifies the pin before extraction; full bootstrap installs it. Upstream MIT license and notices ship inside the ignored addon archive (`addons/limboai/LICENSE.md`, README). Download: https://github.com/limbonaut/limboai/releases/tag/v1.8.1. No engine fork/version change. Desktop runtime evidence does not validate Android/iOS export.

MobDefinition condition rules feed an ACTIVE-only native LimboHSM through LimboMobBrain. Reusable MobBehaviorState instances publish Idle/Wander/Flee/Warn/Chase/Attack/Sleep/Stasis intent. Domain owns stable identity, health/life/corpse state. HSM tasks never move physics bodies. MobLocomotion caches local obstacle/ground probes and steers around blockers/away from edges; MobActor executes physics/combat presentation. This is bounded local steering, not complete navigation/pathfinding. Proxy/regional/stasis retain the existing logical simulation; deactivate native HSM before releasing an actor.

PlayerProfile envelope schema2, identity only player_id: immutable name, level, accumulated character time, appearance/cosmetics, implemented stats, inventory (hotbar/equipment/wallet), future unlock fields. It never stores world seed, world ID, position, surface, textures, animation or combat timers. World metadata stays schema1. WorldSave envelope schema2, identity world_id: global clock/flags/sequence, accumulated world time, player_id -> last world session position, references to checksummed immutable domain/64m-region segments. Segments schema1 cover props, suppression, farms, structures, containers/bags, mobs. Existing P02 terrain index/chunk schema1 stays unchanged in the world directory.

Dirty signals mark only affected region membership. Player capture never calls SurfaceRuntime.snapshot. Eight-second coalescing retains gameplay-safe autosave windows. A player-only inventory mutation writes no world region. A container transfer writes player + affected container region; atomic batch journal roll-forwards ownership documents together. New segments are written/verified before manifest commit. Previous manifest/segment generation retained for recovery; obsolete files in affected segment folders are collected only after commit. First load reconciles all loaded regions once (support-driven removals during restore), not each inventory change. Global clock/session manifest is small and independent of regional payloads. Voxel write-path redesign is R2, untouched.

SchemaMigrations uses explicit ordered N->N+1 callbacks and archives source envelopes. Implemented C01 Player1->2 and World1->2; unknown future schemas safe reject. Old `surface.json` remains recoverable. Pending ownership journal recovers before migration. P04 importer is non-destructive/idempotent, validates original checksum/identity and copied terrain before publishing independent metadata/owners. P04 1m structural sockets cannot safely become 2m occupied footprints: those development pieces are quarantined in `migration/legacy_structures.json`, original world retained. Farm/prop/mob/container state and voxel deltas migrate; unsupported chest contents become bags through the normal support authority, never erased/copied twice. No reset of terrain/player inventories. Full slots or corrupt/future sources stay untouched and report failure; no overwrite of occupied frontend slots.
