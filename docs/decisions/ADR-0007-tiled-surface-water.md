# ADR-0007 — Tiled surface water and reconstructible checkpoints

Status: implemented for R3 C01; final acceptance remains blocked by the native warning described below.

Terrain remains the native voxel/SDF authority. Inland water is a separate heightfield, initialized from the saved generator version/seed/profile hydrology. `WaterGrid` and `WaterTile` are pure data; `WorldWater` is the gameplay facade. No structure becomes a hydraulic barrier. Caves/stacked aquifers and full fluid physics are out of scope.

Use 64m tiles with configurable 2m cells initially: 1,024 cells and 25,600 packed-array bytes per tile. This is four times fewer cells than the suggested 1m starting example; the measured active cost justifies this initial mobile-oriented compromise. Fixed15Hz scheduling processes up to four active tiles per step, round robin, with up to two catch-up steps/frame. Overload slows simulation rather than causing an unbounded catch-up spiral. This is not physical mobile validation. Quiet water sleeps, distant tiles become inactive with hysteresis, and meaningful visited state remains data. Ocean is an analytic infinite reservoir; only edited coast tiles allocate local dynamic data. River upstream/resident-edge sources are explicit bounded external volume, reconstructed from hydrology. Unloaded/inactive edges are closed; this foundation does not claim global offscreen hydrodynamic continuity.

Surface differences transfer depth using double-buffered changes. Four outgoing transfers each use at most24%of previous depth; runtime clamps the configurable bound below25%. Closed domains conserve volume within float32 tolerance. Reservoir/source/precipitation/refill exchanges are accounted separately. Flow-aware sleep prevents a stationary-depth flowing river from being mistaken for still water. Saltwater arriving inland remains saltwater and cannot refill freshwater tools.

`water.json` is a separate checksummed AtomicDocument schema1, keyed by world/model/grid geometry. Only revised tile depth/classification buffers and external-volume accounting persist; base terrain, hydrology, flow, presentation, animation and emitter caches reconstruct. Missing document is the explicit additive migration for existing R1/R2 saves. PlayerProfile and WorldSave schema2/migrators are unchanged; watering-can instance data missing from old inventories defaults empty. Unknown future water schemas reject safely. Terrain's buffered checkpoint must complete before the water document commits. This orders cross-domain checkpoints but is not a distributed atomic transaction; a crash between documents may retain the prior water deviation over newer terrain, which re-equilibrates on reload. Explicit save/quit/transition uses the existing coordinator, and autosave coalesces water writes every4seconds. No water disk write occurs inside a terrain strike.

Presentation is grouped by tile plus one waterfall mesh. It uses depth/flow data, fixed-state visual interpolation, displaced small waves, cutout shoreline foam and at most four shader interaction emitters. Low/Medium/High change wave/foam/emitter budgets only. No screen-space effect or Forward+-only feature is required. Far ocean rendering never allocates solver cells. Shared `WaterMotion` provides bounded buoyancy/current and speed scaling, separate from land combat/motor authority. Finite watering-can litres use the existing item instance/revision system; refill removes the equivalent small m³ volume from resident freshwater.

## Pinned upstream warning / acceptance blocker

Voxel Tools v1.7x `VoxelInstancer::on_area_edited` marks instance blocks modified even when every library item is non-persistent. Stream-out schedules an empty instance save; `VoxelStreamScript` exposes no instance-block persistence API and emits `Tried to save instance block, but VoxelStreamScript does not support them.` The disposable instances are not save truth (project suppression/domain state remains durable). Public APIs offer no local modified-flag clear. Replacing the instancer/library after each edit would globally regenerate foliage and violates R2's local-update budget. Suppressing the warning would hide the issue. No dependency pin was changed.

The minimal upstream correction is to skip scheduling unsupported/empty instance saves. It requires a reviewed native artifact/checksum update; that is deferred explicitly rather than silently rebuilding the pinned extension. R3 C01 cannot receive its warning-free COMPLETE status while this gate fails.
