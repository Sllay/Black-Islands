# S01-RC0-R2 — World Generator v2 / Native Voxel Graph / Foliage / Render Profiles

## Purpose

Heavy correction run before Season 2. R1 must already be complete. This run replaces prototype world-generation/foliage/render foundations with the production Chapter 1 baseline.

Keep scope bounded. Do not add Season 2 content/quests/NPC systems here.

## C01 — Graphics backend + quality profiles

Separate renderer backend from quality preset.

### Renderer backend

Supported launch/export backends:

- `desktop_forward_plus`
- `mobile`
- `compatibility` (`gl_compatibility`)

Renderer selection is startup/export-level state, not a hot-swapped gameplay toggle. Persist desired backend when useful, but only apply it on a safe restart/next launch path if runtime switching is not supported.

### Quality presets

Data-driven Low / Medium / High profiles. These are runtime/application-quality settings and can exist on any compatible renderer backend.

Each profile owns documented budgets such as:

- shadow enabled/disabled and distance/quality
- foliage density multiplier
- foliage LOD distances
- grass interaction radius
- prop visual residency distance
- voxel terrain view/LOD tuning within safe supported ranges
- target render-distance level
- optional post-process/VFX switches

The Options UI created in R1 maps to these profiles. Custom settings override individual profile fields without mutating the source profile resource.

Compatibility profile must not depend on renderer features unavailable in Compatibility.

Validate all gameplay-critical shaders/materials under Mobile and Compatibility paths where practical.

## C02 — Chapter 1 world generator v2

### Replace scripted per-voxel generation hot path

Replace the production `VoxelGeneratorScript` per-voxel island generator with `VoxelGeneratorGraph` / native Voxel Tools graph execution where the world field can be expressed in the graph. The graph is the production base generator.

Reason:

- VoxelGeneratorGraph executes in native Voxel Tools code
- block generation, optimized execution map, subdivision and XZ caching are available
- series generation support helps VoxelInstancer SDF snapping

Project-owned GDScript may configure seeds/profile parameters, orchestrate hydrology/POI metadata and own persistence, but must not loop the entire production voxel volume in GDScript just to generate the base SDF.

Keep project-owned sparse terrain deltas layered over generated base terrain.

### World profile, not hardcoded island constants

Create versioned `WorldGenerationProfile`/equivalent data. Do not leave Chapter 1 geometry hardcoded in `IslandField`.

The current ~480×420 m prototype island is too small. Chapter 1 target baseline is approximately **4× the current land area**, not blindly 4× each linear dimension. Start around ~900–1000 m × ~800–900 m overall island envelope and tune from validation. Exact dimensions remain profile data, not magic constants.

World generation version must be explicit so old saves are not silently interpreted through a new generator.

### Logical elevation model

Terrain remains smooth SDF terrain. Elevation levels are **logical target bands**, not cubic blocks.

Define a profile parameter for elevation step in world meters and use named logical levels.

Dry-land baseline:

- level 0 = common flat/lowland baseline
- generator can rise naturally through levels +1…+4
- player terrain tools may later raise terrain up to +6 relative to the legal local baseline
- player may dig ordinary editable dry land down to -3 where world rules allow

Water shaping:

- rivers primarily occupy -1…-2 target bands
- lakes may use -1…-3 target bands
- banks/basins are smoothly interpolated and procedurally irregular; never perfect cones
- beach transitions from dry land toward shallow sea smoothly
- only a shallow near-shore sea band remains near the player-editable elevation envelope
- deeper ocean rapidly transitions beyond that to large negative depth, target approximately -20 logical levels in deep regions
- deep ocean is not player-editable/buildable Chapter 1 terrain

Generator land does **not** use +5/+6 as normal procedural hills; those are reserved headroom for player terraforming/future systems.

### Macro island shape

Generation pipeline:

Seed
→ profile
→ broad island mask
→ domain warp / coastline irregularity
→ macro lowland/highland field
→ hydro candidate field
→ river/lake decision
→ basin/channel carve
→ beach/coast shaping
→ biome allocation
→ village/POI candidate scoring
→ deterministic prop/foliage seeds
→ validation
→ native voxel graph parameters + world metadata

Do not use raw noise as the whole world design.

### Required terrain character

The island must contain meaningful broad flatter land.

Desired macro shape:

- perimeter/coast and beach
- substantial lowland/plains belt between coast and central highlands
- central/interior may become more irregular/hilly
- highland areas still include usable plateaus/flat pockets
- avoid making the whole interior uniformly bumpy

This is necessary for village/building placement and readable traversal.

### Water counts

Chapter 1 profile keeps the existing design constraint:

- 0–1 major river, or smaller/medium river variants connecting toward sea when selected
- 1–2 small/medium lakes

Hydrology must be seed-driven and profile-valid, not one fixed lake coordinate.

### Village candidate support

Do not build the village yet, but generate/query deterministic candidate regions with scores for:

- flatness/buildability
- water access
- coast distance
- steepness
- flood/basin risk
- enough contiguous usable area

This becomes the contract for later village generation.

## C03 — terrain editing and streaming correctness

### Local edit readiness

Remove dependence on global VoxelEngine `generation == 0 && meshing == 0 && main_thread == 0` for a local edit.

Use area-local readiness/residency. If a local edit must wait a very short time for collision/data readiness, queue/coalesce the gameplay intent rather than silently dropping it.

### Terrain write path

Do not synchronously serialize/readback/rename a durable JSON chunk for every fast terrain strike.

Maintain authoritative in-memory dirty deltas and a crash-safe bounded commit strategy:

- dirty chunk tracking
- coalesce repeated edits
- short journal or equivalent crash-recovery record when needed
- async/budgeted flush where Godot/file API constraints allow
- atomic manifest/checkpoint commit
- explicit forced flush on save/quit/world transition

Correctness > raw speed, but repeated harvesting/terraforming may not stall the render frame on file I/O.

### Streaming level semantics

The UI render-distance setting 2–10 is a **quality level**, not a literal promise of exactly N chunks. Define a documented mapping to horizontal residency/LOD/view distances.

Level 2 is the minimum useful near envelope (current logical center + immediate surrounding neighborhood / roughly 3×3 near coverage where applicable). Level 6 is default. Level 10 is maximum Chapter 1 user-exposed distance.

Use hysteresis around residency boundaries so hovering near a boundary does not constantly spawn/free presentation.

## C04 — VoxelInstancer foliage and prop presentation

Replace the custom patch foliage hot path where VoxelInstancer is appropriate.

### Use VoxelInstancer intentionally

VoxelInstancer is the preferred presentation for natural surface content:

- grass
- small decorative plants
- bushes where non-interactive
- small rocks
- visual tree/rock layers where compatible with gameplay authority

Gameplay resource identity remains project-owned. Do not move harvest truth into arbitrary render instances.

Interactive/persistent resources use a hybrid:

- project-owned stable prop ID/domain state
- VoxelInstancer/MultiMesh presentation when distant/non-interactive
- promoted near interaction/collision adapter only inside gameplay radius

Use VoxelInstancer persistence only if its ID/version semantics are compatible with Black Island save migration; otherwise keep persistence in project domain and use instancer as presentation.

### Grass geometry

Do not use cylinders as grass.

Use a small cluster of alpha-cutout crossed planes/cards. Base near representation can use ~3–4 crossed cards depending on measured cost. Provide reduced mesh LOD(s) over distance, eventually down to a very cheap card/ground blend and disappearance.

Use the actual grass cutout texture asset when available. Configure import/material correctly for alpha cutout/coverage and mipmaps to avoid shimmering.

Grass should visually cover most valid grass biome ground at near/mid range without creating one Node per blade.

### Distance/LOD

Use VoxelInstancer `lod_index`/mesh LOD/fading appropriately:

- grass/small detail at low LOD index and shorter range
- bushes/medium props farther
- trees/large rocks farther again
- use impostor/very cheap far representation only where beneficial

Enable/validate load/unload fading shader path so instances do not pop hard at boundaries.

### Wind

Grass/foliage wind is vertex-shader driven, not per-instance animation scripts.

Requirements:

- world-space noise/phase variation so every blade does not sway identically
- cheap near/mid animation
- farther LODs reduce/disable interaction detail

### Local player/mob grass interaction

Use a bounded shader interaction field (for example one/few world-space influencer positions or a small interaction texture/field) to bend nearby grass around the player and selected nearby actors.

Do not add physics bodies to every blade.

Only near foliage needs interactive bending.

### Destruction/suppression

Sword/tool grass cutting and terrain edits update project-owned suppression/delta state and remove/suppress nearby visual instances without rebuilding an entire large biome.

Prefer VoxelInstancer removal APIs/affected block refresh or narrowly scoped presentation updates.

### Culling

Do not manually destroy every off-camera prop just because frustum culling exists. Structure residency around distance/chunks and let renderer frustum/occlusion/LOD handle visibility inside resident presentation.

MultiMesh batches must remain spatially bounded; one continent-sized MultiMesh defeats fine culling.

Occlusion culling is an optimization layer, not world-state authority.
