# S01-P01 — Boot / Save / Mobile Shell

## Objective

Deliver the first playable Godot 4.7.2 shell: `Boot -> SaveSelect -> Main`, launched from `game/`.

## Scope

- In: exactly four save slots, stable save IDs/metadata schema, atomic-save direction, semantic input actions, landscape/safe-area layout and a separate `SeasonTest` scene.
- In: production HUD regions for Health/Stamina/Mana, movement controls, eight-slot hotbar/inventory button and actions/combat controls; placeholder values are allowed.
- Out: island generation, terrain integration beyond dependency boot sanity, LPC runtime, final player, inventory/combat logic, farming, NPCs and online services.
- Expected files/subsystems: `game/project.godot`, boot/Main/UI/debug scenes, modular save/profile and UI scripts, smoke fixtures; orchestration stays outside `game/`.

## Dependencies and required references

- Begin only after the S01-P00 validated commit, pushed checkpoint and handoff; use an implementation branch, never `main`.
- Read `AGENTS.md`, `harness/prompts/S01-P01-boot-shell.md`, `PLANS.md`, `docs/architecture/REPOSITORY_MAP.md`, `docs/architecture/GAME_ARCHITECTURE.md`, `docs/architecture/SAVE_AND_MIGRATION.md` and ADR-0001 (`docs/decisions/ADR-0001-repository-layout.md`).
- Read boot/UI implementation next. Do not preload world/combat/LPC documents without a direct dependency.
- Keep the P00 toolchain pins; use Godot MCP for engine operations and Serena for existing GDScript symbols.

## Acceptance criteria

1. Exact Godot 4.7.2 imports/opens `game/project.godot`; running the real project reaches Boot/SaveSelect, then selecting/creating a slot enters Main.
2. Four deterministic visible slots use stable IDs/paths and version-ready metadata; save truth belongs to a service, not UI or Node instance IDs.
3. The production HUD and safe-area-aware anchored/container layout survive at least two landscape aspect/resolution simulations; record device limitations separately.
4. Semantic movement/interact/attack/dodge/inventory/build actions exist in Godot InputMap rather than physical keys embedded in gameplay code.
5. `SeasonTest` is separate/reachable; debug controls remain collapsible/disabled in normal production flow.
6. Maintainable smoke checks prove Boot/Main reachability, save UI instantiation and no missing scripts/resources on the tested path.
7. Record commands/results in `harness/build/S01-P01.md`; review secrets, local paths and generated junk; commit/push the validated checkpoint and deliver a compact handoff.

## Checkpoints

- C01: project/input/display settings + Boot/Main.
- C02: four-slot save service/UI + production HUD shell.
- C03: dedicated debug scene + smoke/regression checks + cleanup/handoff. Commit/push validated checkpoints before long manual tests.
- Current state: P01 implemented on `codex/s01-p01-boot-shell`; C01 `7172221`, C02 `f683695`, C03 at branch HEAD. See `harness/build/S01-P01.md` for executed evidence. Do not begin P02 without a separate task.

## Implementation entrypoints

- Production: `game/scenes/boot/Boot.tscn` -> `game/scenes/ui/SaveSelect.tscn` -> `game/scenes/main/Main.tscn`.
- `Profiles` is cross-scene profile authority; `SlotStore` owns schema-1 metadata I/O. `Flow` only navigates. `Profiles.current_profile()` returns a copy; P02 must add world payload/versioning without making UI save authority.
- Production HUD: `game/scenes/ui/ProductionHUD.tscn`; QA: `game/scenes/debug/SeasonTest.tscn`, isolated `user://qa_profiles`.
- Reproduce headless checks: `bash scripts/validate_p01.sh`. Runtime/screenshots require a rendering-capable window/display; headless does not prove native touch/notch behavior.

## Risks

- Desktop aspect simulations do not prove physical safe-area/touch behavior or mobile performance.
- Do not let `Main.gd` or autoloads become dumping grounds; scenes display authoritative save/profile state.
- Stop at the P01 gate; world generation belongs to P02.
