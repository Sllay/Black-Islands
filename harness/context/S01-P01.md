# S01-P01 — Boot, Repository, Save Shell, Mobile Shell

Status: Ready

## Objective

Turn the mapped repository into the first real playable Godot increment without breaking the repository boundary.

## In scope

- Godot 4.7.2 project boot from `game/`.
- real boot flow and `Main` scene.
- four-slot save shell.
- mobile landscape configuration and safe-area-aware UI foundation.
- production HUD shell.
- dedicated debug/test scene with collapsible debug controls.
- initial input map using native Godot input systems where appropriate.
- initial automated smoke test path if practical.

## Out of scope

- final island generation.
- Terrain3D integration beyond any minimal compatibility spike explicitly required.
- full LPC pipeline.
- full inventory/combat/NPC systems.
- online multiplayer.
- external LLM providers.

## Repository constraints

- Godot commands target `game/`.
- documentation/agent/harness files stay outside `game/`.
- no backend-only completion: the phase ends with a bootable and interactable shell.

## Required references

- `AGENTS.md`
- `PLANS.md`
- `docs/architecture/REPOSITORY_MAP.md`
- `docs/architecture/GAME_ARCHITECTURE.md`
- `docs/decisions/ADR-0001-repository-layout.md`

## Acceptance criteria

1. `game/project.godot` opens cleanly in Godot 4.7.2.
2. Running the project reaches a real Main/boot flow, not a script-only harness.
3. Landscape UI foundation respects anchors/safe-area strategy and does not depend on one phone resolution.
4. Four save-slot placeholders can be presented and one can enter the playable shell.
5. A dedicated debug/test scene exists separately from the production scene.
6. Debug controls do not permanently pollute the normal game HUD.
7. No API keys or local secrets are committed.
8. A validated checkpoint is committed and pushed before extended manual testing.

## Checkpoint plan

- C01: boot + Main scene + project display/input shell.
- C02: save-slot shell + production HUD shell.
- C03: debug/test scene + smoke validation + phase handoff.
