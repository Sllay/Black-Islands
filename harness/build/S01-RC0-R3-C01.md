## Architecture / gameplay

See [ADR-0007](../../docs/decisions/ADR-0007-tiled-surface-water.md) and [water interface](../../docs/architecture/WATER_FOUNDATION.md).

- `WaterTile`/`WaterGrid` are pure packed data, never a Node per cell. Configurable64m tiles /2m cells:1024cells,29,696packed bytes/tile.2m initially bounds active cost; it is not the terrain's0.5m voxel resolution.
- R2 seed/profile/version hydrology initializes lakes/rivers. One scheduler uses fixed15Hz steps, up to4active tiles round robin, at most2catch-up steps/frame. Flow-aware sleep; neighboring flow/volume/precipitation/local terrain edits wake water; distant data becomes INACTIVE with hysteresis. No SceneTree access in the solver; workers remain an optional seam.
- Double-buffered capped transfers conserve closed volume within float32 tolerance. Surface gradient produces bounded current; source/ocean/refill exchanges are explicit external volume. Freshwater and finite saltwater are distinguished from infinite ocean boundaries.
- `WorldWater` remains the gameplay query facade. TerrainEditService invalidates only local water columns; sparse saved SDF refresh is independent of delayed collider rebuilding. Ordinary structures are not dams.
- `WaterMotion` supplies buoyancy/current and horizontal speed scaling. Swimming replaces land gravity; it exits back to normal land motor/combat. Existing LPC presentation/fallback retained. No new animation system.
- Watering-can instance module:8L capacity,1L/crop, freshwater refill within4m; equivalent m³ removed from resident water. Old items missing the module start empty. Existing inventory revisions/save IDs remain authoritative.
- Waterfall edges arise from simulated flow across significant height drops; one bounded ribbon mesh presents up to32connections. No volumetric waterfall simulation.
- Ocean stays analytic/infinite-reservoir with cheap horizon presentation. In all3real-world backend smokes, a far-ocean query changed allocated tiles from4to4:0new ocean tiles.
