## C03-B — Effects and weapons

EffectGraph is a cached, allowlisted data DAG: OnUse, OnHit, OnHarvestHit, OnConsume; Damage, ModifyStat, CheckCondition, GiveItem, RemoveItem and registered ApplyStatus/SpawnEntity/PlayEffect seams. Unknown nodes and script/expression fields are rejected. Maximum 256 nodes, 1024 edges, 16 outgoing edges per node and depth 64; iterative cycle validation. No SceneTree Node per effect node. Context prepares detached state and existing InventoryPlan publications commit payment/output/stats before observer notifications. Damage-only attacks do not clone/revise inventory.

Healing fruit proves OnConsume → ModifyStat(health +20). Weapon hits prove OnHit → Damage; conditions prove both branches. ApplyStatus has a representative bounded event hook, not a full status/burn system. SpawnEntity and PlayEffect are trusted adapter seams, not arbitrary scripts.

WeaponDefinition separates six supported classes, damage/speed/movement/knockback/critical/effects from a shared reviewed moveset template. LPC_LAYER resolves the existing `lpc.weapon.sword` through the LPC catalog/compositor. Its upstream slice and `harness/lpc/upstream_slice/CREDITS-selected.csv` are unchanged; no LPC sprites duplicated. DETACHED_SPRITE uses the original placeholder `test_blade.svg`, four direction offsets, texture-sized foot-relative pivot, curves and semantic front/back layers. One reusable rig has a Sprite3D and trail QuadMesh; no per-frame mesh creation. Attack speed synchronizes body animation and combat. Weapon replacement clears old texture/trail state.

Focused review fixed stale trails, pivot sign/dimensions, trail texture, event RNG entropy and playback synchronization. Real physics-frame tests prove open/closed behavior; transaction stale rejection prevented loss before the fix.

## C03-C — Props, harvesting and persistence

SpawnTable version 1 adds deterministic generation-2 placements; legacy generation-1 placement stays unchanged. Private seeded RNG includes world seed, patch, table ID/version. Entries have SURFACE/CAVE domain, biome/material/height/slope/water filters, independent rarity/weight and bounded clusters. CAVE is metadata only; no cave generator. Surface weights Light/Dark/Iron = 12/2/3; Cave = 2/12/8.

Light and Dark Boulder share the same cached base mesh and differ by material/HP/resistance/reserves. Iron MineralRoot is one logical identity/harvest pool with BoulderMesh + OreOverlayMesh. Distant presentation batches both parts in existing regional MultiMeshes; near promotion hides those exact instances, and demotion restores them without duplicating adapters/overlays. No continuously processing script per distant prop.

HarvestToolModule feeds the existing ARK-like extractor. Resistance/quality/affinity/critical affect requested damage, then remaining HP clamps actual damage; reserves remain finite. Resource output, stamina/effect state and ledger HP/reserves publish through one InventoryPlan before observers. The real world MCP found and corrected lowercase ROCK tags; validator now rejects the mismatch.

Root PlayerProfile/WorldSave schema 2 and Inventory schema 2 remain unchanged. Catalog schemas are 1; optional `spawn_table_versions` world flags adopt existing saves additively and reject unknown future table versions. Saves retain IDs and instance state, not copied definitions. Missing item definitions preserve owned stacks using inert diagnostic placeholders; missing harvest definitions preserve frozen HP/reserves and refuse extraction. No save reset. Real DirtyWorldStore manifest/segment tests prove HP/reserves persist on disk; fractional HP comparison uses float tolerance, integer reserves remain exact.
